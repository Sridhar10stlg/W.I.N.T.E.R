```toml
[tool.pytest.ini_options]

```
- `where = ["src"]`: the importable package `winter` lives under `src/`.
- `pythonpath = ["src"]`: lets **pytest** import `winter` without installing. Plain `python` does not see this setting, which is why `pip install -e .` is also needed.

### `src/winter/config.py` (as it stands in the repo)
```python
from typing import Literal

from pydantic import Field, SecretStr, model_validator
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    """All W.I.N.T.E.R configuration lives here, validated once at startup."""

    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    provider: Literal["ollama", "openrouter"] = Field("ollama", alias="LOCAL_AI_PROVIDER")
    model_low: str = Field("gemma3:1b", alias="LOCAL_AI_MODEL_LOW")
    model_high: str = Field("gemma3:4b", alias="LOCAL_AI_MODEL_HIGH")
    ollama_url: str = Field("http://localhost:11434", alias="LOCAL_OLLAMA_URL")
    openrouter_api_key: SecretStr | None = Field(None, alias="OPENROUTER_API_KEY")
    log_level: Literal["DEBUG", "INFO", "WARNING", "ERROR", "CRITICAL"] = Field("INFO", alias="LOG_LEVEL")

    @model_validator(mode="after")
    def _require_key_for_openrouter(self) -> "Settings":
        if self.provider == "openrouter" and not self.openrouter_api_key:
            raise ValueError("OPENROUTER_API_KEY is required when using the OpenRouter provider.")
        return self


def load_settings() -> Settings:
    return Settings()
```
The repo copy also carries explanatory comments on every line. They are omitted here to keep this page short.

## How it works

```
.env file / environment variables  ->  config.py (read + validate)  ->  rest of the app uses settings.model_low
```

- **`.env` is only raw text.** It never checks anything. `config.py` is the code that reads it and validates it.
- **`alias="..."`** is the exact variable name each field reads, such as `LOCAL_AI_PROVIDER`.
- **`Literal[...]`** rejects unknown values (provider typos, bad log levels) at startup.
- **`SecretStr`** shows `**********` when the settings are printed or logged, so the key cannot leak.
- **The validator** compares two fields together: choosing OpenRouter without a key fails immediately.
- **`extra="ignore"`**: unknown variables in `.env` are skipped, not errors.
- **`load_settings()`** is the only place the app reads configuration. Other modules never touch `os.environ`.

### Where a value comes from (highest priority first)
1. A real **environment variable** (set in the terminal or Windows)
2. The **`.env`** file
3. The **default** written in `config.py`

This order lets the same code behave differently on each laptop with no code change.

## Tests (`tests/test_config.py`)

| Test | Proves |
|---|---|
| `test_defaults_use_ollama` | With nothing set, the safe free defaults apply. |
| `test_env_variables_are_read` | The alias names really match the environment. (Would have caught the earlier `WINTER_` vs `LOCAL_AI_` mismatch.) |
| `test_openrouter_requires_key` | Choosing OpenRouter without a key is rejected. |
| `test_openrouter_with_key_is_valid_and_secret_is_hidden` | A key is accepted and never appears in `repr()`. |
| `test_unknown_provider_rejected` | A typo fails loudly instead of falling back silently. |

Every test passes `_env_file=None` so it ignores the real `.env` and gives the same result on every laptop.

## Problems hit and lessons learned

1. **`.env.example` names did not match `config.py`.** The code read `WINTER_*` variables while `.env.example` used `LOCAL_AI_*`. `extra="ignore"` hid the mismatch, so settings silently fell back to defaults. Fix: field aliases in `config.py`, plus a test that reads an environment variable.
2. **`ModuleNotFoundError: No module named 'winter'`** with plain `python -c`. `pythonpath = ["src"]` only applies to pytest. Fix: `pip install -e .` (editable install).
3. **The `.env` typo produced no error.** The terminal session had `LOCAL_AI_PROVIDER=ollama` set as an environment variable, and environment variables override `.env`. Fix: `Remove-Item Env:LOCAL_AI_PROVIDER`. Rule: if a `.env` change seems ignored, check `$env:NAME` first.
4. **`python -c "...import load_settings: load_settings()"`** used `:` instead of `;` between statements.
5. **`src\winter\__init__.py` was missing**, so `winter.__file__` was `None` (Python treated the folder as a loose namespace). Added in Block 2.
6. **Model names:** the first draft defaulted to `llama3.2` models that are not installed. Fixed to the installed `gemma3` models.
