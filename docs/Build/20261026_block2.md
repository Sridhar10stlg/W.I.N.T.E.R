## Goal

A chat loop that talks to any model backend through one narrow interface, and that is built and tested with no real model installed.

## Decisions made in this block

| Decision | Choice | Why |
|---|---|---|
| Provider interface | `Provider.generate(list[Message]) -> str` | One method keeps adapters swappable. |
| Error type | One `ProviderError` | The CLI handles one error type; each adapter translates its own failures. |
| `Provider.name` | Abstract property | A provider that forgets `name` fails at construction, not mid-chat. |
| Mock modes | echo, canned replies, injected error | Covers the happy path and the failure path in tests. |
| Mock selectable in config | `LOCAL_AI_PROVIDER=mock` | Run the whole app with no model installed. |
| CLI testability | `input_fn` and `output_fn` injected into `run_chat` | Tests need no keyboard, screen or model. |
| Failed turn | The unanswered user message is removed from history | A retry never leaves two user turns in a row. |
| Provider selection | One `build_provider(settings)` function, not a registry | No extra layers until needed; Week 3 adds one branch per adapter. |
| Exit codes | 0 ok, 1 provider problem, 2 config problem | Scripts and tests can tell failures apart. |

## How it works

```
.env / environment -> load_settings() -> build_provider() -> run_chat(provider)

CLI ──list[Message]──▶ Provider.generate() ──▶ str reply
                              └─ on failure ──▶ ProviderError ──▶ "[error] ..." line, loop continues
```

- `main()` has three steps, each with its own outcome: config (exit 2 on a bad value), provider (exit 1 if there is no adapter), chat (exit 0).
- Config errors print only the field name and the reason, never the bad value, so a secret can't be echoed.
- Only `ProviderError` is caught in the loop. Any other exception is a bug and shows a traceback on purpose.

## Problems hit and lessons learned

1. **Bugs found in review before they bit.** `MockProvider(replies=[])` behaved like "echo"; an exhausted reply list silently echoed; `Provider.name` was not enforced. All three have regression tests.
2. **A test that could never work.** The first draft of the `main()` test replaced `builtins.input`, but `run_chat` captured the real `input` as a default argument when it was defined, so the swap had no effect. The final test replaces `run_chat` instead. Lesson: default arguments are evaluated once, at definition time.
3. **`set X=Y` is Command Prompt syntax.** In PowerShell it does not set an environment variable, so the app silently used the default. Use `$env:X = "Y"` and `Remove-Item Env:X`.
4. **PowerShell opens at `C:\Windows\system32`** on this laptop. Move to the project folder with `cd` before running anything.
