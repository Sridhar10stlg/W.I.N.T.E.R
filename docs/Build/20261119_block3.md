## Goal

A real local model behind the `Provider` interface: `python -m winter` chats with `gemma3:4b` through Ollama, and every way the call can fail becomes a clear message instead of a traceback.

## Decisions made in this block

| Decision | Choice | Why |
|---|---|---|
| HTTP library | `httpx` ([ADR 0011](../design/decisions/0011-httpx-for-http.md)) | Separate timeout and connect errors; offline tests with `MockTransport`; reusable for OpenRouter. |
| Endpoint | `POST /api/chat` with `"stream": false` | Messages map one-to-one to `list[Message]`; streaming is Month 2. |
| Stop reasons | `stop` -> `complete`, `length` -> `length`, anything else -> `other` | Ollama's words stay inside the adapter ([ADR 0008](../design/decisions/0008-reply-object.md)). |
| Token counts | `prompt_eval_count` / `eval_count` -> `Usage`; bad or missing -> `usage=None` | Bookkeeping glitches never break a chat. |
| Timeout -> | `ProviderTemporaryError` | The only kind the wrapper retries once ([ADR 0010](../design/decisions/0010-timeouts-and-retries.md)). |
| Connection refused, other transport errors, other bad statuses, unreadable reply -> | `ProviderUnavailableError` | The user must act; status number only, never the server's text. |
| HTTP 404 -> | `ProviderSetupError` | Names the model and the `ollama pull` fix; never retried. |
| Bad `LOCAL_OLLAMA_URL` | Validated when the adapter is built; `ProviderSetupError`, exit code 2 | Found by a test: `httpx.InvalidURL` is outside `HTTPError`, so the first question would have crashed. Fail at startup instead. |
| Credentials in URLs | Never printed; messages use scheme, host and port only | ADR 0009 message rules. |
| Factory | `build_provider` builds `OllamaProvider` from `settings.ollama_url`, `settings.model`, `settings.timeout_seconds`, then wraps it in `RetryingProvider` | One composition point. |

## Measured on the Dynabook (2026-11-19)

| Fact | Result |
|---|---|
| `gemma3:4b` first call (cold, after `ollama stop`) | 5.6 s |
| `gemma3:4b` second call (warm) | 0.6 s |
| Where it runs | `100% CPU` (`ollama ps`) |
| Ollama's default context window | 4096 tokens (the model supports 131072) |
| Missing model | HTTP 404, `{"error": "model '...' not found"}` |

These answer open questions 12 (default context size, partly) and 14 (first-call time), and verify the `/api/chat` and CPU assumptions.

## Verified by hand

- Real chat with `gemma3:4b`; the second answer used the first turn (history is sent each time).
- Missing model: clean `[error]`, session stays alive.
- Bad `LOCAL_OLLAMA_URL`: clean `[error]`, exit code 2.
- Ollama not running: clean `[error]`, session stays alive.

## Lessons

- A test found a real crash path (`InvalidURL`) that reading the code had missed.
- `LOCAL_AI_MODEL_TIER=high` in `.env` made my first "model not found" drill use the wrong variable; the tier switch worked as designed.
